- **2008-05-08 — Foldit launches.** A protein-folding game created by the University of Washington **Baker Lab** and **Center for Game Science** establishes the core proposition: human gameplay can become a scientific research instrument.

- **2011-09 — Foldit players solve the M-PMV retroviral protease structure in three weeks.** The result demonstrates that human spatial reasoning and collective search can solve difficult molecular-structure problems that had resisted conventional approaches.

- **2012-09 — Foldit player-guided enzyme design advances the Diels–Alderase project.** Gameplay moves beyond structure prediction into an iterative design → selection → laboratory-testing loop, establishing a precedent for translating player creativity into experimentally testable molecular changes.

- **2019 — qFoldIT development begins as a next-generation extension of the Foldit model.** Following work on *Atomic Heart*, George Ahiakwa begins sustained experimentation at major game-industry events with scientists, testing how Fortnite-derived interaction mechanics can be adapted for scientific tasks rather than entertainment alone.

- **2019–2022 — Gameplay becomes a scientific interaction research program.** George Ahiakwa combines game interaction with laboratory-equipment instructions, molecular-folding mechanics and L-system concepts, testing how scientific workflows can be expressed in both first- and third-person modes and made spatially legible to players.

- **2021-01-25 — QFold is first presented.** The quantum protein-folding algorithm establishes a second lineage alongside Foldit: scientific gameplay is connected not only to human search, but also to emerging **quantum-computational approaches** to **protein-folding prediction**.

- **2022-09 — The “LEGO brick road to open science and biotechnology” vision is published.** The LEGO-like decomposition of scientific work strengthens the conceptual bridge from Foldit’s molecular manipulation to qFoldIT’s later Scientific Object / UAG model.

- **2023-03-22 — Unreal Editor for Fortnite (UEFN) enters Public Beta.** Fortnite becomes a programmable, Unreal-based creation environment with Verse, making the game-engine layer substantially more suitable for persistent scientific worlds, procedural missions and scientific interaction design.

- **2026-08-01 — qFoldIT begins maintaining a development diary in the official Anthropic Claude Science developer conversation.** This marks the transition from a game-science prototype to an openly documented scientific-agent integration program aligned with frontier AI workflows.

- **2026-08-18 — Anthropic publishes “Claude Accelerates Protein Design.”** **Claude Mythos Preview** and **Opus 4.8** autonomously conduct de novo protein-binder design across 15 targets, with at least one **successful binder for 14 targets** and reported **hit rates of 22–35.1%** depending on the experimental setup. For **qFoldIT**, this validates the strategic direction of **connecting human gameplay**, agentic scientific search, computational design and independent laboratory validation into one executable loop.

- **2026-08-20 — Unreal MCP becomes available in UEFN.** Epic embeds an **MCP server** directly in **UEFN**, enabling agents to write/compile Verse, configure devices, create Scene Graph entities, build UMG interfaces and run play sessions. For **qFoldIT**, this turns the engine from a presentation layer into an agent-accessible scientific runtime.

- **2026-08-21 — qFoldIT formalizes its canonical architecture.** Enterprise mission governance, mission contracts, Rust control-plane orchestration, UAG/runtime adapters, scientific validators, evidence/provenance and strategy memory are separated into explicit authority boundaries. This is the decisive transition from “scientific game” to a governed scientific execution platform.

- **2026-08-21 — Pop-Culture / Attention Capture becomes an explicit architectural layer.** LEGO-like construction, original IP and properly licensed external properties, including potential Disney and Warner Bros. Discovery use cases, are treated as engagement and presentation layers above the scientific system, preserving a strict separation between audience acquisition, content rights and scientific authority.

- **2026-08-23 — qfoldit-core becomes the canonical Rust contract layer.** Mission contracts, Scientific Action Envelopes, UAG, submissions, evidence, execution lineage and strategy memory are consolidated into a common systems layer, reducing fragmentation across engines and adapters.

- **2026-08-24 — Enterprise and scientific integration converge.** ***CORPORATE APP*** unifies partner and mission registries; **UEFN-QFOLDIT** formalizes the Mission Contract Bridge and runtime-control boundary; OPENSTRUCTURE validates the same mission-contract and provenance chain independently; scientific MCP adapters adopt the canonical scientific-adapter contract. The development lineage now explicitly spans specialist work associated with Baker Lab, Foldit, Tetrisphere and bioinformatics communities, alongside the wider scientific-engineering network including H3D, Ersilia and independent validation groups.

- **2026-08-25 — qFoldIT reaches its current platform state.** The **Foldit** legacy of human scientific search is extended into a cross-runtime, agent-connected, evidence-bound execution system: enterprise mission → governed contract → AI/human orchestration → UAG → runtime → submission → independent validation → evidence → validated strategy.

- **2026-08-25 — Institutional platform thesis.** **qFoldIT** is positioned as a governed B2B **scientific/Physical-AI** verification pipeline: private runtime nodes can be isolated by organization, scientific authority remains external to gameplay, AI actions remain attributable, and every validated result can be traced from mission intake to scientific evidence.

I lead **qFoldIT**, a scientific technology initiative focused on turning complex scientific and industrial objectives into **interactive, computationally grounded missions** that can be explored by people, AI agents and simulation systems.

The central idea is simple:

> **Make difficult scientific problems understandable, interactive and executable — without separating scientific rigor from human creativity.**

qFoldIT is being developed as a **contract-first scientific mission platform**, connecting scientific computation, canonical scientific representations, AI/MCP workflows, interactive runtimes, validation and auditable contribution records. The architecture is designed so that the same underlying mission can reach research, education, industry and interactive entertainment without losing its scientific semantics.

## Science + Games + AI

One of the principles behind qFoldIT is that a scientific task does not have to choose between:

* a research environment,
* a simulation system,
* an educational experience,
* an AI-assisted workflow,
* or a game.

A single scientific mission can be compiled into different interaction surfaces while preserving the underlying scientific contract.

This is the foundation of **qFoldIT / FoldNite**: scientific discovery presented first as **FUN**, but engineered so that successful interaction can produce structured candidates that proceed into scientific validation.

The game is not the scientific result.

**The validated computational artifact is.**

This distinction is fundamental to the platform architecture. qFoldIT explicitly separates player experience, computational representation and authoritative scientific validation rather than treating a game score or an LLM response as evidence.

## Scientific integrity by design

A core design principle is to keep the boundary between **interaction** and **evidence** explicit.

qFoldIT distinguishes:

* what is implemented and verified;
* what is supported by strong architectural/product evidence;
* what remains a design or roadmap proposition;
* and what originates from an external scientific or technology ecosystem.

The platform architecture also uses a dedicated validation boundary so that protected references and authoritative scientific checks remain on the trusted side of the system.

This is especially important for scientific AI: a plausible output is not automatically a validated result.

## A different model of scientific software

Traditional scientific software often begins with a computational tool and asks people to adapt to it.

qFoldIT explores the opposite direction:

> **Start from the scientific objective, formalise the mission, compile it into an interaction model, let humans and agents search the space, and return only validated outcomes to the scientific layer.**

This creates a path from:

**idea → mission → computation → interaction → candidate → validation → evidence**

rather than:

**idea → isolated software tool**.

## Open scientific ecosystems

qFoldIT is intended to interoperate with existing scientific communities and software ecosystems rather than replace them.

The project currently references and integrates with ecosystems including **FoldIT, OpenStructure, Ersilia, MCP and other open scientific tooling**, while maintaining explicit boundaries around external IP, source code, data, models, publications and trademarks.

The principle is interoperability first:

**connect scientific systems instead of rebuilding every scientific system from zero.**
