# CEPBEP

## Founder & CEO — qFoldIT

I lead **qFoldIT**, a scientific technology initiative focused on turning complex scientific and industrial objectives into **interactive, computationally grounded missions** that can be explored by people, AI agents and simulation systems.

The central idea is simple:

> **Make difficult scientific problems understandable, interactive and executable — without separating scientific rigor from human creativity.**

qFoldIT is being developed as a **contract-first scientific mission platform**, connecting scientific computation, canonical scientific representations, AI/MCP workflows, interactive runtimes, validation and auditable contribution records. The architecture is designed so that the same underlying mission can reach research, education, industry and interactive entertainment without losing its scientific semantics.

## Science + Games + AI

One of the principles behind qFoldIT is that a scientific task does not have to choose between:

* a research environment,
* a simulation system,
* an educational experience,
* an AI-assisted workflow,
* or a game.

A single scientific mission can be compiled into different interaction surfaces while preserving the underlying scientific contract.

This is the foundation of **qFoldIT / FoldNite**: scientific discovery presented first as **FUN**, but engineered so that successful interaction can produce structured candidates that proceed into scientific validation.

The game is not the scientific result.

**The validated computational artifact is.**

This distinction is fundamental to the platform architecture. qFoldIT explicitly separates player experience, computational representation and authoritative scientific validation rather than treating a game score or an LLM response as evidence.

## Scientific integrity by design

A core design principle is to keep the boundary between **interaction** and **evidence** explicit.

qFoldIT distinguishes:

* what is implemented and verified;
* what is supported by strong architectural/product evidence;
* what remains a design or roadmap proposition;
* and what originates from an external scientific or technology ecosystem.

The platform architecture also uses a dedicated validation boundary so that protected references and authoritative scientific checks remain on the trusted side of the system.

This is especially important for scientific AI: a plausible output is not automatically a validated result.

## Research, education and industry

I am interested in building infrastructure that can serve multiple levels of the scientific ecosystem.

### Research

Tools for molecular design, structural biology, computational science, simulation, scientific benchmarking and human/AI collaboration.

### Education

Interactive scientific environments in which difficult concepts can be learned by **doing, manipulating, testing and discovering** rather than only reading about them.

### Industry

Mission-oriented computational workflows for R&D, optimisation, engineering, scientific operations and knowledge capture.

### Scientific software

Composable interfaces between scientific objects, mission contracts, AI agents, simulation runtimes and validation systems.

The long-term objective is to reduce the distance between **scientific intention** and **computable experimentation**.

## Current qFoldIT ecosystem

The public qFoldIT ecosystem includes work around:

* **Mission Contracts** — formal descriptions of scientific objectives and allowed interactions;
* **UAG / Scientific Object Models** — canonical representations separating scientific semantics from a particular runtime;
* **MCP-oriented scientific services** — machine-readable interfaces for AI-assisted scientific workflows;
* **UEFN / FoldNite** — interactive multiplayer scientific missions where FUN is the entry point;
* **OpenStructure integration** — scientific structure validation boundaries;
* **CAMEO-oriented reconciliation** — comparison and reconciliation of candidate outcomes;
* **Corporate / enterprise tooling** — mission orchestration, evidence and organisational workflows;
* **Web / standalone / simulation surfaces** — alternative ways to expose the same underlying scientific mission.

Relevant projects are maintained in the [qFoldIT GitHub organisation](https://github.com/qfoldit).

## A different model of scientific software

Traditional scientific software often begins with a computational tool and asks people to adapt to it.

qFoldIT explores the opposite direction:

> **Start from the scientific objective, formalise the mission, compile it into an interaction model, let humans and agents search the space, and return only validated outcomes to the scientific layer.**

This creates a path from:

**idea → mission → computation → interaction → candidate → validation → evidence**

rather than:

**idea → isolated software tool**.

---

## Open scientific ecosystems

qFoldIT is intended to interoperate with existing scientific communities and software ecosystems rather than replace them.

The project currently references and integrates with ecosystems including **FoldIT, OpenStructure, Ersilia, MCP and other open scientific tooling**, while maintaining explicit boundaries around external IP, source code, data, models, publications and trademarks.

The principle is interoperability first:

**connect scientific systems instead of rebuilding every scientific system from zero.**

## Leadership philosophy

I am interested in building technology at the intersection of:

**Science × Software × AI × Simulation × Human Creativity**

The most important problems are rarely solved by one discipline alone.

The future of scientific computing will increasingly depend on systems that can combine:

* AI agents,

## Building for the long term

The ambition is larger than a single application or game.

The long-term direction is a **scientific mission infrastructure** in which the same objective can move across research, simulation, education and interactive discovery while remaining traceable, reproducible and scientifically governed.

The most interesting question is therefore not:

> *Can a game teach science?*

but:

> **Can an interactive system become a legitimate interface to scientific search?**

That is the question I am building qFoldIT to explore.
